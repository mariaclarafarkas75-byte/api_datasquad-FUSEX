# US13 - Seleção e Persistência de Contexto Acadêmico do Planejamento

## 1. Resumo (User Story)

**Como** professor,
**quero** poder guardar planejamentos antigos,
**para** usar como base em semestres futuros.

---

## 2. Regras de Negócio e Funcionalidades

### 2.1. Pré-requisitos

Informações fundamentais para produção da *User Story*.

* O professor deve estar autenticado no sistema.

* O sistema deve possuir:
  
  * cursos cadastrados;
  * semestres letivos cadastrados;
  * disciplinas atribuídas ao professor;
  * planejamentos previamente gerados.

* Todas as telas relacionadas ao planejamento devem utilizar obrigatoriamente o **Contexto Global Persistente** da aplicação.

---

### 2.2. Contexto Global Obrigatório

O sistema deve possuir um seletor global fixo responsável por determinar o escopo de visualização e operação do professor.

#### Campos obrigatórios

| Campo             | Tipo            | Comportamento                           |
| ----------------- | --------------- | --------------------------------------- |
| Ano               | ComboBox        | Pré-selecionado com o ano atual         |
| Semestre do Ano   | ComboBox/Toggle | 1º ou 2º semestre                       |
| Curso             | ComboBox        | Apenas cursos relacionados ao professor |
| Semestre do Curso | ComboBox        | Semestres válidos do curso selecionado  |

---

#### Campo variável

| Campo      | Tipo     | Comportamento                    |
| ---------- | -------- | -------------------------------- |
| Disciplina | ComboBox | Disciplinas do curso selecionado |

O campo acima só deve ser exibido para professores ou coordenadores.

---

### 2.3. Persistência do Contexto

O contexto selecionado deve permanecer ativo durante toda a sessão do usuário.

#### Regras obrigatórias

* Ao navegar entre telas:
  
  * Planejamento;
  * Estatísticas;
  * Temas;
  * Rotina;
  
  o contexto deve permanecer preservado.

* O sistema não deve exigir nova seleção de:
  
  * ano;
  * semestre;
  * curso;
  * semestre do curso;
  * disciplina (para professores e coordenadores)
  
  após troca de tela.

* Alterações no contexto devem atualizar automaticamente:
  
  * disciplinas visíveis;
  * planejamentos exibidos;
  * estatísticas;
  * horários;
  * temas relacionados.

---

### 2.4. Visualização de Planejamentos Antigos

O professor deve conseguir acessar planejamentos de períodos anteriores através do seletor global.

#### Regras obrigatórias

* Ao selecionar:
  
  * um ano anterior;
  * ou um semestre letivo anterior ao atual;
  
  o sistema deve entrar automaticamente em modo somente leitura.

Semestres superiores ao atual não podem ser selecionados.

---

### 2.5. Modo Somente Leitura

Planejamentos antigos não podem ser alterados.

#### Comportamentos obrigatórios

* Todos os campos editáveis devem ficar desabilitados.

* Botões de:
  
  * salvar;
  * editar;
  * excluir;
  * cancelar aulas;
  
  devem ficar desabilitados visualmente.

* O sistema deve exibir banner fixo indicando:

> `"Você está visualizando um período passado — modo somente leitura"`

---

### 2.6. Atualização Reativa do Sistema

Sempre que o contexto global for alterado, todas as telas abertas devem ser atualizadas automaticamente.

#### Informações afetadas

| Informação     | Atualização  |
| -------------- | ------------ |
| Planejamento   | Recarregado  |
| Estatísticas   | Recalculadas |
| Temas          | Filtrados    |
| Disciplinas    | Filtradas    |
| Horários       | Atualizados  |
| Rotina semanal | Atualizada   |

---

### 2.7. Isolamento por Contexto

Cada planejamento deve existir exclusivamente dentro de um contexto acadêmico específico.

#### Combinação obrigatória

```text
Ano + Semestre do Ano + Curso + Semestre do Curso + Professor
```

#### Regras

* Planejamentos de contextos diferentes não podem ser misturados.

* Alterações em um semestre não podem impactar:
  
  * semestres anteriores;
  * outros cursos;
  * outros períodos letivos.

---

### 2.8. Organização Histórica

O sistema deve manter os planejamentos organizados historicamente.

#### Objetivos

* Facilitar consulta de períodos anteriores;
* Permitir acompanhamento evolutivo da disciplina;
* Garantir preservação histórica;
* Evitar perda de informações acadêmicas.

---

### 2.9. Soft-Delete e Preservação Histórica

Mesmo que ocorram alterações futuras:

* disciplinas removidas;
* mudanças de carga horária;
* troca de professor;
* alteração curricular;

os planejamentos antigos devem permanecer íntegros e acessíveis.

#### Regra obrigatória

Nenhum planejamento histórico pode ser apagado fisicamente do banco de dados.

---

### 2.10. Navegação entre Períodos

O professor deve conseguir alternar rapidamente entre períodos letivos.

#### Comportamentos esperados

* Troca instantânea de contexto;
* Recarregamento automático da interface;
* Preservação da navegação atual;
* Sem necessidade de logout/login.

---

## 3. Critérios de Aceite (Definition of Done)

1. O professor deve conseguir selecionar Ano, Semestre do Ano, Curso, Semestre do Curso e Disciplina através do seletor global.
2. O contexto selecionado deve permanecer persistido durante toda a navegação.
3. Alterações no contexto devem atualizar automaticamente todas as telas relacionadas.
4. Planejamentos antigos devem abrir automaticamente em modo somente leitura.
5. O sistema deve exibir banner visual indicando períodos históricos.
6. O professor não deve conseguir alterar dados de períodos passados.
7. Planejamentos devem permanecer organizados corretamente por contexto acadêmico.
8. Alterações em um período não devem afetar períodos anteriores.
9. O sistema deve preservar planejamentos históricos mesmo após alterações curriculares.
10. A troca entre contextos deve ocorrer sem necessidade de reiniciar a aplicação.

---

## 4. Comportamentos Esperados da Interface

### 4.1. Estrutura sugerida da interface

```text
+-----------------------------------------------------------------+
| Contexto Global                                                 |
| Ano | Semestre | Curso | Semestre do Curso | Disciplina         |
+-----------------------------------------------------------------+

+-----------------------------------------------------------------+
| Banner de Somente Leitura (quando aplicável)                    |
+-----------------------------------------------------------------+

+----------------------+------------------------------------------+
| Planejamento         | Estatísticas                             |
|                      |                                          |
| Lista de aulas       | Indicadores                              |
| Temas                | Progresso                                |
| Rotina               | Carga horária                            |
+----------------------+------------------------------------------+
```

---

### 4.2. Comportamentos UX obrigatórios

* Minimizar quantidade de cliques;
* Atualização automática sem recarregar a aplicação;
* Contexto sempre visível;
* Navegação contínua entre períodos;
* Feedback visual claro sobre modo leitura/escrita.

---

## 5. Notas Técnicas

### 5.1. Estrutura recomendada

Sugere-se utilização de um objeto global observável:

```java
ContextoGlobal
```

Contendo:

```java
ano
semestreAno
curso
semestreCurso
disciplina
```

---

### 5.2. Atualização reativa

Recomenda-se utilizar:

* `ObjectProperty<ContextoGlobal>`
* `Bindings`
* `ChangeListener`
* `BooleanBinding`

Para atualização automática das telas.

---

### 5.3. JavaFX sugerido

* `ToolBar` fixa no topo;
* `ComboBox`;
* `ToggleButton`;
* `HBox`;
* `BorderPane`;
* `Bindings` em `disableProperty()` para modo leitura.

---

### 5.4. Regra sugerida para read-only

```java
boolean somenteLeitura =
    contextoSelecionado < periodoAtual;
```

---

## 6. Regras de Persistência

* O contexto atual da sessão deve permanecer acessível globalmente.
* Planejamentos históricos devem permanecer armazenados indefinidamente.
* Dados históricos não podem ser sobrescritos automaticamente.
* Toda navegação deve respeitar o contexto selecionado.
