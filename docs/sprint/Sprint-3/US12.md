# US12 - Visualização de Estatísticas do Planejamento

## 1. Resumo (User Story)

**Como** professor,
**quero** poder visualizar as estatísticas do planejamento, como quantidade de aulas distribuídas para cada tema, aulas ministradas, aulas ainda não ministradas e aulas canceladas,
**por conta de** algum imprevisto.

---

## 2. Regras de Negócio e Funcionalidades

### 2.1. Pré-requisitos

Informações fundamentais para produção da *User Story*.

* As estatísticas devem ser exibidas dentro do contexto global obrigatório da aplicação:

  * **Ano**
  * **Semestre do Ano**
  * **Curso**
  * **Semestre do Curso**
* O professor só pode visualizar estatísticas das disciplinas às quais estiver atribuído no contexto selecionado.
* As estatísticas dependem da existência prévia de:

  * Planejamento gerado automaticamente;
  * Temas cadastrados;
  * Atribuições de horários;
  * Slots de planejamento vinculados à disciplina.
* Caso não exista planejamento gerado para o contexto atual, o sistema deve exibir uma mensagem clara:

  > `"Nenhum planejamento foi gerado para este contexto."`
* Para períodos passados, o sistema entra automaticamente em **modo somente leitura**, permitindo apenas visualização dos dados históricos.

---

### 2.2. Estatísticas Gerais do Planejamento

O sistema deve apresentar um painel consolidado contendo métricas derivadas automaticamente dos dados do planejamento.

#### Indicadores obrigatórios

| Indicador                            | Descrição                                                         |
| ------------------------------------ | ----------------------------------------------------------------- |
| **Total de Temas**                   | Quantidade total de temas cadastrados para a disciplina           |
| **Aulas Geradas por Tema**           | Quantidade de slots atribuídos a cada tema                        |
| **Aulas Ministradas**                | Total de aulas confirmadas como ministradas                       |
| **Aulas Não Ministradas**            | Total de aulas ainda pendentes                                    |
| **Aulas Canceladas pelo Professor**  | Quantidade de slots cancelados manualmente pelo professor         |
| **Aulas Canceladas pela Secretaria** | Quantidade de slots cancelados pelo ADM                           |
| **Avaliações Restantes**             | Quantidade de temas marcados como avaliação ainda não ministrados |
| **Percentual de Conclusão**          | Percentual da carga horária concluída                             |
| **Carga Horária Mínima**             | Valor configurado pelo coordenador                                |
| **Total de Aulas Geradas**           | Quantidade total de slots gerados pelo sistema                    |

---

### 2.3. Cálculo das Estatísticas

Todas as estatísticas devem ser derivadas automaticamente dos registros do planejamento.

#### Regras obrigatórias

* O professor **não pode editar estatísticas manualmente**.
* Toda alteração de status de aula deve atualizar os indicadores imediatamente.
* O cálculo do percentual de conclusão deve seguir a fórmula:

```text
(Aulas Ministradas / Carga Horária Mínima) × 100
```

* Slots cancelados:

  * não contam como aulas ministradas;
  * permanecem visíveis no planejamento;
  * devem ser considerados separadamente por origem:

    * cancelamento do professor;
    * cancelamento da secretaria.

---

### 2.4. Atualização em Tempo Real

As estatísticas devem refletir automaticamente alterações realizadas no planejamento.

#### Eventos que disparam atualização automática

| Evento                           | Impacto                                            |
| -------------------------------- | -------------------------------------------------- |
| Aula marcada como ministrada     | Incrementa aulas ministradas                       |
| Aula marcada como não ministrada | Incrementa aulas pendentes                         |
| Cancelamento pelo professor      | Atualiza contagem de cancelamentos                 |
| Cancelamento pelo ADM            | Atualiza contagem de cancelamentos administrativos |
| Inclusão/remoção de tema         | Reprocessa distribuição de aulas                   |
| Regeneração do planejamento      | Recalcula todos os indicadores                     |

#### Comportamento esperado

* Não deve ser necessário atualizar manualmente a tela.
* Os componentes visuais devem utilizar propriedades observáveis (`ObservableList`, `Bindings`, `IntegerProperty`, `DoubleProperty`) do JavaFX.
* O painel estatístico deve permanecer sincronizado com:

  * lista de aulas;
  * status dos slots;
  * dados de temas;
  * carga horária da disciplina.

---

### 2.5. Visualização por Tema

O sistema deve permitir detalhamento individual por tema.

#### Informações exibidas por tema

| Campo                       | Descrição                             |
| --------------------------- | ------------------------------------- |
| Nome do Tema                | Nome cadastrado pelo professor        |
| Quantidade de Aulas Geradas | Total de slots associados ao tema     |
| Quantidade Ministrada       | Aulas concluídas daquele tema         |
| Quantidade Pendente         | Aulas ainda não ministradas           |
| Quantidade Cancelada        | Slots cancelados relacionados ao tema |
| É Avaliação?                | Identifica se o tema é avaliativo     |
| É Opcional?                 | Identifica temas opcionais            |

---

### 2.6. Indicadores Visuais

As estatísticas devem possuir destaque visual para facilitar leitura rápida.

#### Regras visuais sugeridas

| Situação                           | Indicador Visual               |
| ---------------------------------- | ------------------------------ |
| Aula ministrada                    | Verde                          |
| Aula pendente                      | Amarelo                        |
| Aula cancelada                     | Vermelho                       |
| Percentual concluído ≥ 100%        | Barra completa verde           |
| Percentual abaixo da meta esperada | Barra parcial laranja/vermelha |

#### JavaFX sugerido

* `ProgressBar` para conclusão da carga horária;
* `PieChart` para distribuição de status das aulas;
* `BarChart` para aulas por tema;
* `TableView` para detalhamento dos temas;
* `Tooltip` exibindo informações adicionais ao passar o mouse.

---

### 2.7. Cancelamentos e Impacto Estatístico

#### Cancelamentos pelo Professor

* O professor pode cancelar um ou mais slots informando obrigatoriamente:

  * motivo;
  * horários afetados.
* O sistema deve:

  * alterar o status para `cancelada_professor`;
  * atualizar imediatamente as estatísticas;
  * manter o histórico do motivo.

#### Cancelamentos pela Secretaria

* Slots impactados por cancelamentos administrativos devem:

  * receber status `cancelada_adm`;
  * exibir o nome do ADM responsável;
  * exibir o motivo do cancelamento;
  * bloquear qualquer edição pelo professor.
* Cancelamentos administrativos devem atualizar automaticamente os indicadores do professor.

---

### 2.8. Projeção de Conclusão (Funcionalidade Sugerida)

O sistema pode exibir previsão automática de cumprimento da carga horária.

#### Cálculo sugerido

* Média de aulas ministradas por semana;
* Quantidade restante de aulas;
* Quantidade restante de semanas letivas válidas.

#### Possíveis estados

| Situação           | Resultado                                           |
| ------------------ | --------------------------------------------------- |
| Ritmo suficiente   | `"Carga horária será concluída dentro do semestre"` |
| Ritmo insuficiente | `"Risco de não conclusão da carga horária"`         |

---

### 2.9. Utilização de Sábados

Caso o algoritmo utilize sábados para completar a carga horária mínima:

* O sistema deve informar:

  * quantidade de sábados utilizados;
  * datas utilizadas;
  * quantidade de aulas alocadas nesses sábados.
* Esses slots devem participar normalmente das estatísticas.

---

## 3. Critérios de Aceite (Definition of Done)

1. O professor deve conseguir visualizar estatísticas automaticamente ao abrir um planejamento válido.
2. O sistema deve atualizar os indicadores imediatamente após qualquer alteração no status de uma aula.
3. O percentual de conclusão deve refletir corretamente a carga horária ministrada.
4. Cancelamentos do professor e da secretaria devem aparecer separadamente.
5. O professor não deve conseguir editar estatísticas manualmente.
6. O sistema deve funcionar corretamente em modo somente leitura para períodos passados.
7. O detalhamento por tema deve apresentar quantidades coerentes com os slots gerados.
8. A tela deve permanecer sincronizada após regenerações do planejamento.
9. Indicadores gráficos e tabelas devem refletir exatamente os dados persistidos no banco.
10. O sistema deve manter histórico dos motivos de cancelamento.

## 4. Comportamentos Esperados da Interface

### 4.1. Estrutura sugerida da tela

```text
+------------------------------------------------------+
| Contexto Global                                      |
| Ano | Semestre | Curso | Semestre do Curso          |
+------------------------------------------------------+

+----------------------+-------------------------------+
| Painel Estatístico   | Planejamento                  |
|                      |                               |
| % conclusão          | Lista de aulas                |
| Aulas ministradas    | agrupadas por data            |
| Aulas pendentes      |                               |
| Cancelamentos        |                               |
| Gráficos             |                               |
+----------------------+-------------------------------+

+------------------------------------------------------+
| Tabela de Temas                                      |
+------------------------------------------------------+
```

---

### 4.2. Comportamentos UX obrigatórios

* Atualização automática sem recarregar tela;
* Exibição visual clara dos status;
* Minimização de cliques;
* Informações estatísticas sempre visíveis simultaneamente ao planejamento;
* Feedback visual imediato após alterações.

### 5.1. Estruturas recomendadas

#### Entidades relacionadas

```text
Planejamento

Tema
Disciplina
AtribuicaoProfessor
```

---

### 5.2. Status possíveis do SlotPlanejamento

```text
nao_ministrada
ministrada
cancelada_professor
cancelada_adm
```

---

### 5.3. Sugestão de propriedades observáveis JavaFX

```java
IntegerProperty aulasMinistradas;
IntegerProperty aulasPendentes;
IntegerProperty aulasCanceladas;
DoubleProperty percentualConclusao;
ObservableList<EstatisticaTemaDTO> temas;
```

---

### 5.4. Atualização reativa

Recomenda-se utilizar:

* `Bindings.createDoubleBinding(...)`
* `FilteredList`
* `ObservableList`
* `ChangeListener`
* `BooleanBinding`

Para manter os painéis estatísticos sincronizados automaticamente.
